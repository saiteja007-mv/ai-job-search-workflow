Run the career-ops daily pipeline end to end for the AI/ML Engineer search in <CAREER_OPS_DIR>.

GOAL: 10 high fits, counted ONLY when tsenta confirms the application status is COMPLETED. Plus real verified outreach contacts, Unipile connection requests, and dashboard updates.

This task DOES apply. It does NOT send LinkedIn invites - outreach is drafted and staged for human review only (disabled 2026-09-09). It still never fabricates.

STEP 0 — Load the rules. cd to <CAREER_OPS_DIR>. Read modes/_custom.md, config/profile.yml (targeting, location, comp — authoritative, do not hardcode), modes/_profile.md, modes/oferta.md, modes/_shared.md, and cv-aiml.md + article-digest.md (the ONLY source of truth for any résumé, report, or outreach claim — every skill, metric, tool, employer and date must trace there; keywords may be reordered or reframed, never invented).
Work authorization (sponsor targeting ON): the candidate is on <YOUR_WORK_AUTH_STATUS> (<YOUR_SPONSORSHIP_NEEDS>). A plain "no sponsorship" line is NOT a reject (current work authorization covers the start) but ranks below sponsor-evidenced employers; PREFER direct employers with recent H-1B/LCA filings for the title and E-Verify enrollment, and H-1B cap-exempt employers. A clause barring F-1/OPT/CPT/EAD/STEM OPT/the I-983 training plan, or requiring US citizenship / security clearance / ITAR / export control / US person / polygraph / public trust, is a HARD SKIP. Respect data/blacklist.md.

STEP 1 — Scan. Pull candidates from all of these, deduping by job id:
  (a) tsenta `get-job-recommendations`. CRITICAL: query by `maxYearsExperience` (try 3, then 4), NOT by `jobTypes`. tsenta's seniority taxonomy is unreliable — a <TARGET_COMPANY> req tagged "Entry Level, yoe=2" turned out to say "Director level" in the JD body, and filtering by jobTypes hides whole bands of valid roles. Paginate until hasMore is false. Do not pass `search` alongside other filters (returns FILTERS_NARROW).
  (b) `node scan.mjs --since 3 --json` (curated boards, live reqs only).
  (c) `node scan-ats-full.mjs --since 5 --include-undated --json`. ALWAYS pass --include-undated: without it the sweep silently drops ~16,000 postings whose ATS exposes no date field, and those are live. Check `postingsDroppedNoDate` in the output before concluding a sweep was complete.

STEP 2 — Shortlist. US-located, entry/mid AI/ML titles (Machine Learning Engineer, AI/ML Engineer, Applied AI / GenAI Engineer, MLOps / ML Platform, LLM / NLP / Deep Learning, "Software Engineer, AI/ML"). Drop non-US, Senior/Staff/Lead/Principal/III+/Manager/Director, interns, and known cleared-work shops (CACI, Booz Allen, Leidos, SAIC, Peraton, ManTech, Northrop, Raytheon, Lockheed, Anduril, Parsons, MITRE, GRVTY, <FEDERAL_CONTRACTOR>). Deprioritize aggregator relists (<TARGET_COMPANY>) — they consistently score under 3.0 with no concrete requirements.

STEP 3 — Gate (this is THE apply decision). For each shortlisted role:
  (a) Fetch the FULL JD (`get-jobs-by-ids` with descriptionMaxChars 8000, or fetch-job-description). NEVER score an unread JD, and never score from feed metadata — read the JD body.
  (b) Grep the full text for citizen|clearance|ITAR|export control|polygraph|public trust|OPT|CPT|F-1|EAD and read each in context. A bar on current status = hard skip.
  (c) Score 0.0–5.0 on the career-ops rubric against cv-aiml.md. Fan out with the Workflow tool (one agent per JD) when more than ~8.
  CALIBRATION: honest ceiling ~4.4; ≥4.5 is rare. 5+ yrs required, a Manager/Director title, or a senior comp band → cap 2.5–3.0. A comp band topping out below the profile's floor is disqualifying. A core REQUIRED skill absent from cv-aiml.md is a real deduction (distinguish required from preferred). Consulting / client-services / forward-deployed / staff-aug rank below product ML engineering. A stub or aggregator JD caps at 3.5. NEVER inflate a score to hit the count — a wrong apply costs a credit and a recruiter's attention. Zero survivors on a given day is a valid outcome; report it honestly.

STEP 4 — Apply, ONLY to ≥4.0 survivors.
  ASHBY IS SUPPORTED — apply to it like any other ATS. Do NOT route it to manual. An earlier version of this task claimed tsenta failed 4/4 on jobs.ashbyhq.com; that is obsolete, and it blocked a 4.4-scoring SF role for a full day before being caught. Verified COMPLETED on Ashby 2026-08-11: <TARGET_COMPANY> x5, <TARGET_COMPANY> x2, <TARGET_COMPANY>, <TARGET_COMPANY>. Do not re-add this rule without fresh FAILED evidence from the current week.
  `apply-to-job` with jobIds (carries the JD → optimized résumé). If applying by url, ALWAYS pass jobDescription too or the résumé ships un-optimized. EMAIL IDENTITY (2026-10-21, user rule): every career-ops application uses <YOUR_EMAIL>. Omit resumeProfileId (default profile = contact@) for every company, including ones applied under the legacy legacymail address; never pass the legacy legacymail profile.
  OVER-QUEUE ~2x. Roughly 40% of applies come back JOB_EXPIRED (the feed is not liveness-checked); those are refunded, so queuing extra is cheap. To land 10 confirmed, expect to apply to ~16–18.
  Then poll `get-application-status` for each. Approve any at PENDING_RESUME_REVIEW via `approve-application`. Verify isOptimized:true. Poll to terminal. COMPLETED = counts. FAILED / SKIPPED(JOB_EXPIRED) = does NOT count. Spot-check one optimizedProfile per run for fabrication.
  DO NOT count tsenta's own native auto-applies toward the 10 — it applies unvetted daily (it has submitted plainly non-AI/ML roles). Count only applications this run submitted through the ≥4.0 gate.

STEP 5 — Outreach. For each company with a COMPLETED application, find real LinkedIn contacts via the Unipile helper (POST {UNIPILE_API_BASE}/linkedin/search then /users/{public_id}; key in <CAREER_OPS_DIR>\.env as UNIPILE_API_KEY, account <UNIPILE_ACCOUNT_ID> — never print the key). Prefer in-house technical recruiter, then hiring manager, then same-team IC. VERIFY current employer from the headline — agency/third-party recruiters do not count. Max 2 per company. If none verify, return none rather than padding.
  Draft a connection note per contact: <=300 characters (count it), first person, no em dashes, no flattery, naming the specific role applied to plus ONE concrete hook grounded in cv-aiml.md. **DO NOT SEND. Sending from this task is disabled as of 2026-09-09.** Write the verified contacts and their drafted notes to <CAREER_OPS_DIR>/reports/runs/{YYYY-MM-DD}-outreach-staged.md and stop there. Do NOT call POST /users/invite, /chats, or any other Unipile send endpoint. A human approves every LinkedIn send. Reason: raw-API sends bypass the career-ops outreach ledger, writing entries with ts:null that are invisible to check_contacted and to every recency-based duplicate guard, which risks double-contacting people an interactive session has already approached. When outreach is wanted, it goes through the linkedin MCP (send_invitation / send_message) in an interactive session after review.
